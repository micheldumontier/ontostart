# OntoStart: engine, collection and template

Status: agreed 2026-11-13. Replaces the one-ontology-per-branch layout.

## Goals

1. Keep all of Michel's ontologies in one repository, built by one pipeline.
2. Let anyone create their own repository, with their own w3id.org identifier, from a template, and get pipeline fixes by bumping a version tag.
3. Let students publish a tutorial ontology under `https://w3id.org/ontostart/sandbox/<name>/` without opening a w3id.org pull request.
4. Every IRI that resolves today keeps resolving at every step of the migration.

## Non-goals (follow-ups)

- A "root ontology" mode where `https://w3id.org/<id>/` is a single ontology rather than a catalogue.
- Automatic purging of sandbox ontologies at the end of a term.
- Versions taken from git tags instead of being committed back by CI.

## Repositories

| Repository | Role |
|---|---|
| `micheldumontier/ontostart` | **Engine** (Python package `ontostart`, reusable workflows `build.yml` and `w3id-pr.yml`, tagged `v1`, `v1.1`, ...) **and the collection** (Michel's ontologies). Keeps the existing GitHub Pages site and w3id.org identifier. |
| `micheldumontier/ontostart-template` (new) | GitHub template repository: `ontostart.yaml`, the example ontology `testo`, two ~15-line caller workflows pinned to `@v1`. |

## Repository layout (collection and template)

```
ontostart.yaml
ontologies/<name>/<name>.ttl          curated ontology (+ versions/, README.md, optional catalog-v001.xml, imports/)
sandbox/<name>/<name>.ttl             tutorial ontology (only on main via PR, or on branch sandbox/<name>)
apache/web/<w3id>/.htaccess           generated by `ontostart htaccess`, proposed to w3id.org
```

`<name>` matches `^[a-z0-9][a-z0-9-]*$`. Reserved names: `sandbox`, `versions`, `docs`, `catalog`, `main`, and every key of `aliases`.

## Statuses

| Status | Set by | Site |
|---|---|---|
| `stable` | default for `ontologies/` | normal |
| `experimental` | `ontostart.yaml` | banner: generated or still changing; may change without notice |
| `sandbox` | any folder under `sandbox/` | banner: tutorial ontology, not persistent, may be removed |

## `ontostart.yaml`

```yaml
w3id: ontostart                                   # https://w3id.org/ontostart/
pages: https://micheldumontier.github.io/ontostart
gist_id: 9affe51b863c5144fa82d7b1d23449aa         # badges; empty disables them
sandbox: true
foops: true
term_docs: ontospy                                # or "site"
aliases:                                          # old path -> current path
  testo: sandbox/testo
legacy_root:                                      # /x.y.z of the retired root ontology
  path: main
  name: ontostart
ontologies:
  suloized-pizza:
    status: experimental
    compare_unsatisfiable_with: imports/pizza.owl
```

## What CI does

| Event and ref | Targets | Bump + commit back | Publish |
|---|---|---|---|
| push to `main` | folders with changed files (all, if `ontostart.yaml` changed) | yes | yes |
| push to `sandbox/<name>` | `sandbox/<name>/` only | yes | yes |
| push to any other branch, or pull request | folders with changed files | no | no |
| manual run | one folder or all; bump is an input (default no) | per input | yes, on `main` and `sandbox/*` |

Per target: OWL DL profile check, HermiT reasoning (with the folder's `catalog-v001.xml` when present), version bump, four syntaxes, OntoSpy and pyLODE docs, FOOPS! (if enabled), site page.

A target is **blocked** (not committed, not published, run fails at the end) when the profile check fails, the ontology is inconsistent, reasoning errors, its ontology IRI is not `https://w3id.org/<w3id>/<path>/`, or its unsatisfiable-class count differs from `compare_unsatisfiable_with`. Unsatisfiable classes alone do not block.

One run makes at most one commit to the ref and one push to `gh-pages`. Runs on the same ref never overlap.

## Published layout (GitHub Pages, `gh-pages` branch)

```
index.html, catalog.{ttl,jsonld,nt,owl}       catalogue of every folder that has meta.json (DCAT: stable + experimental)
<path>/index.html                              ontology page (status banner, badges, downloads, docs, versions)
<path>/meta.json                               name, path, status, title, description, iri, version, versions, modified
<path>/versions/{x.y.z,latest}/<name>.{ttl,jsonld,nt,owl}
<path>/<x.y.z>/index.html                      version landing page
<path>/docs/{ontospy,pylode}/, <path>/foops/
main/, testo/                                  archived, never rewritten
```

`<path>` is `<name>` for curated ontologies and `sandbox/<name>` for sandbox ones. Badge files in the gist are `ontology-ci-<kind>-<safe>.json`, `<safe>` = `<path>` with `/` replaced by `-`, kinds `profile reason version ontospy pylode deploy foops`.

## Redirects (`https://w3id.org/<w3id>/...`)

| Path | Goes to |
|---|---|
| `/` | catalogue (HTML) or `catalog.<ext>` (RDF) |
| `/catalog.<ext>` | `catalog.<ext>` |
| `/sandbox`, `/sandbox/` | catalogue |
| `/<name>/...`, `/sandbox/<name>/...` | that ontology, with today's sub-rules: ontology, `x.y.z`, `versions/...`, `<file>.<ext>`, `docs`, terms, pass-through |
| `/<alias>/...` | the aliased path, directly to GitHub Pages (no w3id.org self-redirect) |
| `/x.y.z` | `legacy_root` archive |

The `.htaccess` never lists ontologies, so new ontologies and sandbox entries need no w3id.org pull request. Content negotiation, 303-only, CORS and `Vary` rules stay as today. Root-level term IRIs of the retired `ontostart.ttl` (e.g. `/hasUnit`) stop resolving; nothing is known to use them.

## Security

- Workflow inputs reach shell only through `env:`.
- `robot.jar` v1.9.8 is checked against a pinned SHA-256 and run with `java -jar`.
- Third-party actions pinned by commit SHA.
