# OntoStart

OntoStart publishes FAIR (Findable, Accessible, Interoperable, Reusable) OWL ontologies with GitHub Actions. This repository holds two things:

* the **engine**: the Python package `ontostart` (`src/ontostart/`) and the reusable workflows `build.yml` and `w3id-pr.yml`, tagged `v1`, `v1.1`, ...
* the **collection**: Michel Dumontier's ontologies, one folder each, built by the engine.

What you get for every ontology:

* a w3id.org persistent identifier, with versioned IRIs
* content-type negotiation to get the ontology in different syntaxes
* rich ontology metadata, as per the FAIR principles
* GitHub Actions that check the OWL 2 DL profile and consistency (ROBOT with HermiT), bump the version on commit, write Turtle, RDF/XML, JSON-LD and N-Triples files, generate documentation (OntoSpy and pyLODE), run a FOOPS! FAIRness assessment, and publish a website to GitHub Pages

A template repository, `micheldumontier/ontostart-template`, for publishing your own collection under your own w3id.org identifier is coming soon. It doesn't exist yet.

The catalogue of all of them is at <https://w3id.org/ontostart/> (site: <https://micheldumontier.github.io/ontostart/>).

* **stable**: the default for folders under `ontologies/`.
* **experimental**: set in `ontostart.yaml`; the site shows a banner. `suloized-pizza` is generated by ontointegrator from the Manchester Pizza ontology.
* **sandbox**: every folder under `sandbox/`; tutorial ontologies, not persistent, may be removed.

Retrieve the ontology in different syntaxes, or a specific version:

```
curl -L -H "Accept: text/turtle" https://w3id.org/ontostart/pizza/
curl -L -H "Accept: application/rdf+xml" https://w3id.org/ontostart/pizza/
curl -L -H "Accept: application/ld+json" https://w3id.org/ontostart/pizza/
curl -L -H "Accept: application/n-triples" https://w3id.org/ontostart/pizza/
curl -L -H "Accept: text/turtle" https://w3id.org/ontostart/pizza/1.0.1
curl -L https://w3id.org/ontostart/pizza/BakingDuration    # term page in a browser
```

The retired root ontology `ontostart.ttl` is archived on GitHub Pages under `main/`; its `/x.y.z` IRIs still resolve.

## Repository layout

```
ontostart.yaml                    collection configuration
ontologies/<name>/<name>.ttl      curated ontology (+ versions/, README.md, optional catalog-v001.xml, imports/)
sandbox/<name>/<name>.ttl         tutorial ontology
apache/web/ontostart/.htaccess    w3id.org redirects, generated by `ontostart htaccess`
apache/tests/redirects.tsv        expected redirects
apache/test-redirects.sh          redirect tester
src/ontostart/, tests/            the engine and its tests
.github/workflows/                build.yml, ontostart.yml, w3id-pr.yml, engine-tests.yml
docs/classroom.md                 how students publish a sandbox ontology
```

`<name>` matches `^[a-z0-9][a-z0-9-]*$`. `sandbox`, `versions`, `docs`, `catalog`, `main` and the keys of `aliases` are reserved.

## What CI does

| Event and ref | Targets | Bump and commit back | Publish |
|---|---|---|---|
| push to `main` | folders with changed files (all, if `ontostart.yaml` changed) | yes | yes |
| push to `sandbox/<name>` | `sandbox/<name>/` only | yes | yes |
| push to any other branch, or pull request | folders with changed files | no | no |
| manual run | one folder or all; the bump is an input (default no) | per input | yes, on `main` and `sandbox/*` |

Per target: OWL DL profile check, HermiT reasoning (using the folder's `catalog-v001.xml` when present), version bump, four syntaxes, OntoSpy and pyLODE docs, FOOPS! (if enabled), site page.

A target is **blocked** (not committed, not published, and the run fails at the end) when the profile check fails, the ontology is inconsistent, reasoning errors, its ontology IRI is not `https://w3id.org/<w3id>/<path>/`, or its unsatisfiable-class count differs from `compare_unsatisfiable_with`. Unsatisfiable classes alone do not block. One run makes at most one commit to the ref and one push to `gh-pages`; runs on the same ref never overlap.

The site is published on the `gh-pages` branch: a catalogue at the root (`index.html`, `catalog.{ttl,jsonld,nt,owl}`) and, for each ontology, its page, `meta.json`, `versions/`, `docs/` and `foops/`. Set Pages to "Deploy from a branch", `gh-pages`, `/` root.

## `ontostart.yaml`

```yaml
w3id: ontostart                                   # https://w3id.org/ontostart/
pages: https://micheldumontier.github.io/ontostart
gist_id: 9affe51b863c5144fa82d7b1d23449aa         # badges; empty disables them
sandbox: true
foops: true
term_docs: ontospy                                # or "site"
aliases:                                          # old path -> current path
  testo: sandbox/testo
legacy_root:                                      # /x.y.z of the retired root ontology
  path: main
  name: ontostart
ontologies:
  suloized-pizza:
    status: experimental
    compare_unsatisfiable_with: imports/pizza.owl
```

## Publishing a sandbox ontology

Students and workshop participants copy `sandbox/testo/` to `sandbox/<name>/`, rename the file, and push a branch `sandbox/<name>`. CI publishes it at `https://micheldumontier.github.io/ontostart/sandbox/<name>/`, with the IRI `https://w3id.org/ontostart/sandbox/<name>/`. No w3id.org pull request is needed. See [docs/classroom.md](docs/classroom.md).

## Redirects

`https://w3id.org/ontostart/...` is served by `apache/web/ontostart/.htaccess`:

| Path | Goes to |
|---|---|
| `/` | the catalogue (HTML), or `catalog.<ext>` for RDF requests |
| `/<name>/...`, `/sandbox/<name>/...` | that ontology: the ontology itself, `x.y.z`, `versions/...`, `<file>.<ext>`, `docs`, terms |
| `/testo/...` | alias of `/sandbox/testo/...` |
| `/x.y.z` | the archived root ontology |

The `.htaccess` never lists ontologies, so new ontologies and sandbox entries need no w3id.org pull request.

Regenerate and test it:

```
uv run ontostart htaccess
bash apache/test-redirects.sh                                   # local Apache in Docker
bash apache/test-redirects.sh --targets                         # also check the GitHub Pages targets exist
bash apache/test-redirects.sh --url https://w3id.org/ontostart  # the live redirects
```

## Proposing redirects to w3id.org

Run the `Propose w3id.org redirects` workflow (`w3id-pr.yml`). It tests the redirects and opens a pull request against [perma-id/w3id.org](https://github.com/perma-id/w3id.org/pulls). Before running it, sync your fork of `perma-id/w3id.org` so the pull request is based on current content. The `W3ID_TOKEN` secret is a classic personal access token with the scopes `repo`, `read:org` and `workflow`.

## Secrets and variables

* `GIST_TOKEN` (secret): classic PAT with the `gist` scope, used to write the badge data.
* The badge gist is a public gist; its id is `gist_id` in `ontostart.yaml`.
* `W3ID_TOKEN` (secret): see above.
